Play Detach

What it does

The Play Store updates apps on its own, even when auto-update is turned off for them. Play Detach hides the apps you choose from the Play Store, so it never offers or installs updates for them.

The apps themselves are not changed. They keep working, and you can update them by hand at any time.

How to use it

  1. Find the app in User apps or System apps. The search box matches app names and package names.
  2. Turn on the switch next to it. The change applies right away and the Play Store is restarted, no reboot needed.
  3. The Detached tab lists every detached app. Turn a switch off to let the Play Store see that app again.

Apps marked Not installed are still on your list but no longer on the phone. They stay detached, so a patched app you reinstall is protected right away. To clear them out, tap Remove in the note at the top of the Detached tab, or turn them off one by one.

Sideloaded apps

Apps marked Sideloaded were not installed by the Play Store: APK files, other stores, patched apps, apps restored from a backup app, or apps installed with adb or a root shell. Android remembers which app installed each package, and every app whose installer is not the Play Store counts as sideloaded. Long-press an app to see its installer under Installed by.

The Play Store can still replace these apps with its own version and undo a patch, so they are the apps you usually want to detach.

In User apps, tap Sideloaded to show only them, then Detach all to detach every one of them with one tap. Detach all always works on the apps in the list you see, so it also works together with the search box. You are asked before anything changes.

Several apps at once

Tap Select in User apps, or long-press any app and choose Select several apps. Tap apps to mark them, then Detach or Re-attach in the bar at the bottom. Select all marks every app in the current list. Tap the X to stop selecting.

App menu

Long-press an app to open its menu:

  • Installed by - which app installed it: the Play Store, the package installer (an APK file), a backup app, another store, or unknown (adb, a root shell or the ROM).
  • Open in Play Store - opens the app's page, an easy way to check that a detached app no longer shows an Update button.
  • Select several apps - starts selecting with this app already marked.
  • Copy package name - for the command line or a detach.txt.

Backup and restore

The module keeps its backups in its own folder, Play-Detach in internal storage (/sdcard/Play-Detach), created when the module is installed. If you delete that folder, backups go to Download instead; installing the module again creates the folder again.

Open the Detached tab: a row of buttons appears right under the tabs. Back up opens the Play-Detach folder: change the file name if you like, or go to another folder, and tap Save here. Restore opens the same folder: tap the backup file. Re-attach all clears the whole list after you confirm.

Automatic backup. After every change the list is also saved to play-detach-auto.txt in the same folder, and Restore shows it first as Automatic backup. An empty list never replaces it, so after Re-attach all you can still get the old list back. Turn it off or on with the Automatic backup switch in the Back up and Restore windows, or with play-detach autobackup off / on.

Restoring replaces the current list with the one in the file. Backups are plain text files with one package per line, so you can also edit them or use them as detach.txt. They stay on your storage when the module is removed.

Status line

  • Active in Play Store - the module is working in the Play Store.
  • Applies when the Play Store opens - the list changed after the Play Store last started; it is saved and loads the next time the Play Store opens.
  • Problem - the module could not start in the Play Store. The message shows the reason; see Troubleshooting below.

Orange right after a change is normal. When you turn a switch on or off, the Play Store is closed and the new list is saved. The dot stays orange until the Play Store starts again and loads the new list, then it turns green. Open the Play Store once, or just wait until it starts in the background.

Command line

Everything in this page can also be done from a terminal with root. In Termux the short command play-detach is installed as well.

Show detached apps
su -c '/data/adb/modules/play-detach/play-detach list'
Detach one or more apps
su -c '/data/adb/modules/play-detach/play-detach add com.example.app'
Re-attach an app
su -c '/data/adb/modules/play-detach/play-detach remove com.example.app'
Re-attach everything
su -c '/data/adb/modules/play-detach/play-detach clear'
Check if the current list is active
su -c '/data/adb/modules/play-detach/play-detach status'
Back up the list to the Play-Detach folder
su -c '/data/adb/modules/play-detach/play-detach backup'
Restore a backup
su -c '/data/adb/modules/play-detach/play-detach restore /sdcard/Play-Detach/play-detach-backup.txt'
Restore the automatic backup
su -c '/data/adb/modules/play-detach/play-detach restore /sdcard/Play-Detach/play-detach-auto.txt'
Turn the automatic backup off (on again with on)
su -c '/data/adb/modules/play-detach/play-detach autobackup off'
All commands
su -c '/data/adb/modules/play-detach/play-detach help'

Detach apps at install time

Put a file named detach.txt in the root of the module zip, with one package name per line. The apps in it are detached while the module installs. Lines starting with # are ignored.

How it works

Play Detach is a Zygisk module. It loads only into the Play Store process. When the Play Store asks the system whether a detached app is installed, the module changes that request, so the system answers that the app does not exist.

The list is stored in /data/adb/play-detach/detach.list, one package per line. Nothing outside the Play Store is touched.

Requirements

  • arm64 device with Android 10 or newer
  • A working Zygisk: ReZygisk, Zygisk Next or NeoZygisk on KernelSU, SukiSU-Ultra or APatch, or Zygisk enabled in Magisk
  • zygisk-detach must not run at the same time, both modules change the same Play Store calls. If it is installed, Play Detach copies its detached apps during install and offers to remove it (Vol+), keep it (Vol-), or disables it if no key is pressed

Troubleshooting

If an app still shows up in the Play Store, close the Play Store, clear its cache in system settings and open it again. Then check the module log:

su -c 'logcat -d -s PlayDetach'

A line with active in Play Store means the module works. Any other message names the step that failed, for example a missing Zygisk or a change in a new Android version.

How it is built

  • Zygisk library - C++20, built with Android NDK r29 for arm64-v8a. Uses Zygisk API v4, so it runs on ReZygisk, Zygisk Next, NeoZygisk and Magisk. No third-party libraries. Every read from Play Store binder data is bounds-checked, and on anything unexpected the call is passed through untouched.
  • Command line tool - a plain shell script. The list is written to a temporary file and then swapped in, so the Play Store never reads a half-written list.
  • WebUI - plain HTML, CSS and JavaScript with no frameworks and no build step. App names and icons come from the root manager's WebUI API. Fonts are bundled, so it works offline.
  • Build - one build.sh script builds the whole module from source.

Tested on

Poco F6 Pro with the Xiaomi.eu ROM (Android 16), SukiSU-Ultra and ReZygisk. Other devices should work but were not tested.
